# 採用版と修正記録

## 状態を分ける

「提案」「試作」「制作上の固定」「採用」「投稿用へ反映」「予約登録」「公開」を別々に記録します。ファイル名にlatestと書かれていても採用記録より優先しません。

この資料集の『ためし部』の4コマは2026年11月11日の採用稿、こよみの紹介は11月9日の採用稿です。『瀬尾家』の「宿題の先生」は元チャットで最新として指定されたv12です。画像内の日付や版は制作当時のものです。

## 1件ごとに残す項目

作品、話数または回、タイトル、原稿版、採用状態、制作日、採用日、画像寸法、ファイル、参照画像の役割、使用プロンプト、追加修正、文字配置などの後処理、確認結果を残します。

日付とv番号だけでは修正順を確定できない場合があります。この資料集でも同じv2名で複数の局所指示が保存されているため、指示を一覧として収録し、存在しない中間画像を作らない方針にしています。

## ファイル名の例

```text
episode01_strip02_art_v1.png
episode01_strip02_review_v2.jpg
episode01_strip02_adopted.jpg
script.json
reference-map.json
```

ファイルの役割は名前だけでなく、[素材一覧](../assets-manifest.json)の説明でも確認できます。旧版を上書きしないで保存し、採用した後に投稿用画像、ZIP、確認用一覧をそろえます。

## 公開前の区切り

採用した画像でも、pixivなどで公開済みとは限りません。予約投稿で見せる時期を優先する場合は、GitHubに含める作例の公開時期も合わせます。このパッケージはレビュー用で、外部公開はしていません。

## 内容の版と配布先の移行

同じPDFを新リポジトリへ移すだけなら、PDF内部の版数とSHA-256を保持します。新しいReleaseタグは配布単位を識別するものです。アプリごとに異なっていたファイル名は[対応表](../releases/pdf-migration.csv)で一つの配布ファイルへ対応付け、既存サンプルIDや言語キーを変えません。旧ファイル名を一括置換しないでください。
